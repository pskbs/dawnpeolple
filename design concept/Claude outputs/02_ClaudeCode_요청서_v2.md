### 0-2. 일하는 방식
- **작게 나눠서 진행**해요. 각 단계 끝에 (1) 무엇을 했는지 3~5줄 요약 (2) 제가 직접 해야 할 일 (3) 다음 단계를 알려주세요.
- 저는 **비개발자에 가깝게** 설명받길 원해요. 결과 위주로, 짧고 실행 가능하게 말해주세요.
- 제 PC는 **Windows**예요. 터미널 명령은 PowerShell 기준으로 안내해 주세요.
- **초반에는 앱을 먼저 만들고 로컬에서 테스트**할 수 있는 상태까지 가세요. 배포와 앱인토스 연동은 그 다음이에요.
- 확신이 없는 기술적 판단(특히 토스 로그인 mTLS, Supabase 세션 발급)은 **작은 PoC로 먼저 검증**하고 결과를 알려주세요.
- 아래는 **묻지 말고 진행**해도 돼요: 파일 생성, 의존성 설치, 마이그레이션 작성, 로컬 테스트, 커밋·푸시.
- 아래는 **반드시 먼저 물어보세요**: 유료 리소스 생성, 운영 DB의 파괴적 변경(drop/truncate), 실서비스 배포, 외부 계정 설정 변경, API 키가 필요한 작업.

### 0-3. Git 규칙 (자동 커밋·푸시)
- 저장소: GitHub `pskbs` 계정, **서비스당 저장소 1개**. 저장소명은 서비스명 확정 후 영문 소문자로 저에게 확인받고 만드세요.
- 작업 단위마다 **자동으로 커밋하고 푸시**해요. 커밋 메시지는 Conventional Commits(`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`)로 쓰고 본문은 한국어 가능해요.
- 기본 브랜치는 `main`이에요. 큰 변경은 `feat/...` 브랜치에서 작업 후 병합하세요. `push --force`, `reset --hard` 같은 파괴적 명령은 쓰지 마세요.

## 1. 프로젝트 개요 (상위 기획)

| 항목 | 내용 |
|---|---|
| 시장 | 야간근무 시장 |
| 타깃 | 저녁에 출근해 새벽에 퇴근하는 사람들(간호사, 자영업, 프리랜서, 서비스·제조·물류 교대근무자 등). 만 19세 이상 |
| 문제 | 낮 시장에는 퇴근 후 지인·소모임·놀거리가 많지만, 새벽 퇴근자는 환경상 어렵고 대부분 혼자 귀가해 시간을 보내요 |
| 솔루션 | ① 새벽 퇴근자끼리 **오프라인 벙개**로 만나는 소모임 ② 근무 중·퇴근 후 **온라인 커뮤니티(수다방)** 로 소통 |
| 수익 | 앱인토스 인앱 광고. 확장 시 추가 모델 검토 |
| 해자 | 미정. 후보: 근무 리듬(퇴근 시간대) 기반 필터, 야간 장소 정보 축적, 브랜드 정체성 |
| 배포 | ① 앱인토스 미니앱 ② 일반 웹 ③ 추후 iOS/Android 스토어 앱(단독) |
| 서비스명 | **새벽사람들**(표기 "새벽사람들 in 부천") |
| 오프라인 시작 지역 | **부천** 우선. 온라인(수다방)은 전국 오픈. 지역은 **설정값**으로 관리(코드 하드코딩 금지), 부천 위주로 진행한다는 안내를 곳곳에 표시 |

### 포지셔닝 (중요)
- 앱인토스에는 **"커뮤니티 + 모임"** 으로 등록해요. 소개팅·만남 서비스로 분류되면 법인 등록 확인, 성인인증, 24시간 내 신고 대응, 프로필 검증이 필수인데, 현재 사업자는 개인사업자(배우자 명의)라서 분류를 피해야 해요.
- 그래서 앱 안 문구·스토어 설명·약관에 **소개팅, 연애, 짝, 썸, 이성, 매칭** 같은 표현을 쓰지 않아요.
- **성별·연령으로 걸러서 만나게 하는 기능**(이성만 참가, 성별 필터, 1:1 매칭)을 만들지 않아요. 성별·연령대는 벙개 **참석 현황 안내**로만 사용해요.
- **누구나 벙개를 개설**할 수 있으므로 신고·차단·제재·개설 한도·자동 필터를 반드시 구현해요(5-3). 검수의 UGC·만남 유사 서비스 요건을 참고해 선제 대응해요.

## 2. 확정된 결정사항

| 항목 | 결정 |
|---|---|
| 서비스명 | **새벽사람들** (표기: "새벽사람들 in 부천"). `BRAND_NAME="새벽사람들"`, `REGION_LABEL="부천"` 상수로 관리. 앱인토스 네비게이션 바에는 **콘솔에 등록한 앱 이름과 동일하게** 표시해야 하므로, "in 부천"은 인트로·벙개모임 상단·수다방 배너 등 **앱 내부 표기**로 사용해요. 콘솔 등록명은 제가 최종 확정해요 |
| 메뉴(탭) | **벙개모임 / 수다방 / 내정보** |
| 수다방 | **카테고리 없는 스레드(Threads)형 SNS 피드**. 누구나 아주 쉽게 짧은 글을 올리고, 댓글·좋아요가 달리는 구조 |
| 벙개 개설 | **누구나 개설 가능**. 대신 신고·차단·개설 제한·자동 필터 필수. 설정값 `bungae_create_role`(`all` 또는 `admin_only`, 기본 `all`) |
| 벙개 지역 | **"부천"을 기본값으로 고정 바인딩** + 상세 위치(선택, 역·동 단위로 유도) |
| 회원 유형 | 1가지(일반 회원). 운영자 권한은 `profiles.role = 'admin'` 별도 플래그 |
| 연령 | 만 19세 이상만 가입. 토스 로그인의 **생일을 필수 동의**로 받아 판별. 웹은 출생연도 입력 + 만 19세 이상 확인 체크 |
| 익명성 | 닉네임 사용. 실명·연락처 저장 금지 |
| 닉네임 | **야간 테마로 자동 생성**(가입 시), 이후 변경 가능(기본 7일에 1회, 설정값) |
| 로그인 | **1단계 웹: Supabase Auth**, **2단계 앱인토스: 토스 로그인**. 로그인은 교체 가능한 어댑터 구조 |
| 벙개 소통 | 벙개 상세의 **참석자 전용 댓글**만. 1:1 DM·채팅 없음 |
| 연락처·외부 메신저 | 금지하지 않음. 약관과 화면 안내로 안전 수칙만 제공 |
| 참석자 정보 | 참석 신청한 사람에게만 **닉네임 + 성별 + 연령대**(예: 20대 후반) 공개. 미참석자에게는 "N자리 남았어요"만 |
| 탈퇴/연결 해제 | 계정·프로필 삭제 + 작성글·댓글 함께 삭제. 토스 연결 해제 콜백 수신 시에도 동일 처리 |
| AI | 비속어·불법·선정 콘텐츠 1차 필터, 위기 문구 감지(**모든 글 대상, 작성자에게만 도움 안내**). 로컬은 `claude -p`, 배포는 Anthropic API |
| 광고 | 수다방 글 작성 완료·벙개 개설 완료 시 **전면형(빈도 제한)**, 글·벙개 상세 하단 **배너** |
| 디자인 | **밤하늘(딥네이비) + 달·별**, 입체적이고 귀여운 캐릭터. **토스 검수 대비 테마 2종**(`hybrid` 기본 제출용 / `night` 전면 야간) |

## 3. 기술 스택 & 아키텍처

### 3-1. 스택
| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | **Vite + React + TypeScript (SPA)** | 앱인토스 WebView는 **정적 번들을 업로드**(압축 해제 100MB 이하)하는 방식이라 SSR(Next.js)과 맞지 않아요 |
| UI | **TDS(토스 디자인 시스템)** + 필요한 부분만 커스텀 CSS | 검수 요건. WebView용 TDS 패키지명/사용법은 공식 문서에서 확인 |
| 라우팅 | React Router | 뒤로가기 동작 검수 대응 |
| 데이터/인증/스토리지 | **Supabase**(Postgres + RLS + Auth) | 이미 사용 중 |
| 웹 배포/서버리스 | **Vercel** | 웹 배포 + `api/` 서버리스 함수(토스 로그인 프록시, AI 호출) |
| AI | Anthropic API(배포) / `claude -p` CLI(로컬) | 비용 절감 |
| 테스트 | Vitest(단위) + Playwright(핵심 시나리오) | 로컬 검증 |
| 배포 대상 3종 | 웹(Vercel), 앱인토스(`.ait` 번들), 스토어 앱(추후 Capacitor 등 래핑 가능하도록 설계) | |

> 스택 판단이 문서와 충돌하면(예: 앱인토스가 특정 프레임워크/빌더를 요구) 문서를 따르고 이유를 알려주세요.

### 3-2. 플랫폼 어댑터 (가장 중요한 설계)
앱인토스 전용 코드가 앱 전체에 퍼지지 않도록 **플랫폼 경계**를 만드세요. 환경변수 `VITE_PLATFORM=web|toss`(추후 `native`)로 구현체를 선택해요.

```
src/platform/
  index.ts            // 현재 플랫폼 어댑터를 export
  types.ts            // 인터페이스 정의
  web/                // Supabase Auth, 웹 공유, (광고 없음 또는 stub)
  toss/               // appLogin, 토스 공유, 토스 광고, 네비게이션/뒤로가기
```

어댑터가 다룰 기능:
- `auth`: 로그인/로그아웃/현재 사용자/탈퇴
- `share`: 링크·초대 공유
- `ads`: 배너/전면(웹에서는 no-op)
- `nav`: 뒤로가기·종료·헤더(웹에서는 토스 Navigation을 흉내 내는 자체 헤더)
- `env`: 안전영역, 플랫폼 식별

### 3-3. 빌드 타깃
- `pnpm dev` — 로컬(웹 플랫폼)
- `pnpm build:web` — Vercel용
- `pnpm build:toss` — 앱인토스 번들(문서의 빌드 명령 사용)
- `pnpm test`, `pnpm lint`, `pnpm typecheck`

### 3-4. 폴더 구조(제안)
```
/
  CLAUDE.md
  docs/                 # apps-in-toss-notes.md, decisions.md, terms 초안 등
  supabase/migrations/  # SQL 마이그레이션 (전부 버전 관리)
  api/                  # Vercel 서버리스 함수 (auth-toss, ai-moderate 등)
  src/
    config/             # brand.ts, regions.ts(오픈 지역 설정), flags.ts, copy.ts(전체 문구), nickname-words.ts
    platform/
    features/           # onboarding, bungae, feed(수다방), me, moderation
    components/
    lib/
    styles/themes/      # night.css, hybrid.css (색 토큰)
  public/illustrations/ # 마스코트/일러스트 (초기엔 SVG placeholder)
```

## 4. 진행 단계 (Phase)

각 Phase 끝에 **완료 기준**을 스스로 검증하고 보고하세요.

### Phase 0 — 조사 & 셋업
- 0-1의 문서 읽기 → `docs/apps-in-toss-notes.md`
- 디자인 참고 폴더 확인 → `docs/design-reference/`, `docs/design-notes.md` (10-2)
- 저장소·`.gitignore`·`CLAUDE.md`·`.env.example`·Vite+React+TS 골격
- Supabase 프로젝트 연결 확인(CLI 또는 대시보드 안내), Vercel 프로젝트 연결 안내
- **완료 기준**: 로컬에서 빈 앱이 실행되고, 첫 커밋·푸시 완료, 노트 저장

### Phase 1 — 웹 앱 MVP (로컬 테스트 가능)
- DB 마이그레이션 + RLS(5장, 6장)
- Supabase Auth 로그인(이메일 우선, 소셜은 추후), 온보딩, 벙개, 수다방, 내정보, 신고/차단, 관리자 최소 화면
- 콘텐츠 필터 v1(금칙어) + AI 필터 인터페이스(`mock`/`claude-cli` provider)
- 시드 데이터 스크립트(테스트 유저·글·벙개, **로컬 전용**)
- `night`/`hybrid` 테마 토큰 구조, `copy.ts`와 `docs/copy-list.md`(화면별 문구 표)
- **완료 기준**: 핵심 시나리오 E2E 통과(가입 → 온보딩 → 글쓰기·댓글·좋아요 → 벙개 개설(일반 회원) → 참석 신청 → 참석 현황 노출 → 신고 → 탈퇴). 제가 로컬에서 직접 눌러볼 수 있게 실행 방법을 3줄로 안내

## 5. 기능 명세 (하위 기획)

모든 화면 문구는 **해요체**, 긍정형, 능동형이에요. 비속어·은어·과한 유행어는 앱 고정 문구에 쓰지 않아요.

### 5-0. 컨셉 문구 & 문구 관리 (중요)
- **모든 화면 문구는 `src/config/copy.ts` 한 곳**에서 관리하고, 화면별 문구 목록을 `docs/copy-list.md`(화면 / 위치 / 문구 / 비고 표)로 함께 만들어 주세요. 앱이 나오면 제가 이 표를 보고 문구를 수정할 거예요.
- **핵심 컨셉 메시지**: "낮에만 모임 있나요? 새벽에 일하는 우리도 있어요!"
  낮에 일하는 사람들만 모임·수다·놀거리 환경이 잘 갖춰져 있다는 문제의식에서 만들었고, **새벽에 일하는 사람들도 여기 있다**는 뜻을 짧고 눈에 띄게 전달해요. 아래 후보 중 1안을 기본으로 넣고, 나머지는 `copy.ts`에 대안으로 남겨 주세요.

| 안 | 문구 | 용도 |
|---|---|---|
| 1(기본) | **낮에만 모임 있나요? 새벽에 일하는 우리도 있어요!** | 인트로, 수다방 상단 배너 |
| 2 | 새벽에도 우리가 있어요 | 짧은 태그라인(헤더 보조, 로딩, 공유 미리보기) |
| 3 | 퇴근이 새벽인 사람들, 여기 모여요 | 벙개모임 상단, 서비스 소개 |

- **문구 노출 위치**
  1. **인트로 화면**(첫 진입, 로그인 전): 1안을 크게, 그 아래 "새벽사람들 in 부천"
  2. **수다방 피드 최상단 고정 배너**: 1안(작은 카드, 스크롤하면 사라짐)
  3. **수다방 글쓰기 화면 상단**: "새벽에 일하는 우리끼리, 편하게 남겨요"
  4. **벙개모임 목록·개설 화면 상단**: 3안 + 지역 안내(아래)
  5. 공유 미리보기·서비스 소개: 2안
- **지역 안내 문구**(곳곳에 표시): "지금은 **부천** 지역 위주로 진행돼요. 곧 다른 지역도 열릴 거예요."
  - 벙개모임 목록 상단(항상 노출, 닫기 없음), 벙개 개설 화면, 온보딩 지역 선택 화면, 인트로 화면에 넣어 주세요.
  - 수다방은 전국 어디서나 이용할 수 있다는 점도 함께 안내해요("수다방은 어디서나 이용할 수 있어요").
- 글쓰기 입력창 placeholder는 아래 문구를 돌아가며 보여줘요(설정값): "오늘 퇴근길은 어땠어요?", "지금 뭐 하고 있어요?", "야식 뭐 먹을까요?", "오늘 근무는 어땠어요?"
- 앱 문구에 **소개팅, 연애, 짝, 썸, 이성, 매칭** 표현은 쓰지 않아요.

### 5-1. 탭 구조
하단 탭(앱인토스에서는 **토스 플로팅 탭바**만 사용, 자체 탭바 금지): **벙개모임 / 수다방 / 내정보**
- 앱인토스 네비게이션 바에는 등록한 앱 이름(새벽사람들)이 표시돼요. "in 부천"은 위 5-0의 앱 내부 영역에 표기해요.

### 5-2. 첫 진입 & 온보딩
1. **인트로 화면**: 5-0의 컨셉 문구와 서비스 설명(토스 로그인 사용 시 필수), 지역 안내
2. 로그인(플랫폼 어댑터)
3. 온보딩 입력
   - **닉네임**(필수): 아래 자동 생성 규칙. "다시 뽑기" 버튼(가입 전에는 횟수 제한 없음), 직접 입력도 가능
   - **성별**(필수): 토스 로그인 제공값 사용. 웹은 직접 선택
   - **연령**(필수): 토스 생일 또는 웹 출생연도 → 만 19세 미만은 가입 불가 안내
   - **지역**(필수): 시/도 → 시/군/구(전국). 부천 밖 지역이면 "지금은 부천 위주로 진행돼요" 안내와 함께 가입은 가능
   - **근무 유형**(선택): 간호·의료 / 사장님·자영업 / 서비스·판매 / 제조·물류 교대 / 프리랜서·크리에이터 / 기타. 선택 시 "닉네임 옆에 보여줘요" 토글(기본 켬, 언제든 변경 가능)
   - **퇴근 시간대**(선택): 밤 12~3시 / 새벽 3~6시 / 아침 6~9시 / 불규칙
   - **동의**: 서비스 이용약관, 개인정보 처리방침, 만 19세 이상 확인
4. 가입 후 `terms_agreements`에 동의 버전과 시각 저장

**닉네임 자동 생성 규칙**
- 형식: `형용사 + 명사` (+ 필요 시 숫자 2~3자리로 중복 회피). 예: "졸린 올빼미", "느긋한 달토끼", "배고픈 별똥별", "따끈한 해장국", "든든한 가로등"
- 단어 목록은 `src/config/nickname-words.ts`에 두고, **야간·새벽 감성**(올빼미, 달, 별, 첫차, 가로등, 새벽공기, 야식, 커피, 고양이, 부엉이 등)으로 구성하세요. 비속어·은어·특정 인물·상표는 넣지 않아요. 단어 조합 전체에 금칙어 필터를 적용해요.
- 길이 2~12자, 중복 불가, 특수문자 제한. 가입 후 변경은 **7일에 1회**(설정값 `NICKNAME_CHANGE_DAYS`)

### 5-3. 벙개모임 (오프라인 모임)
**개설 — 누구나 가능** (설정값 `bungae_create_role`, 기본 `all`)
- 리더(개설자)가 입력하는 항목:
  - 제목(30자 이내), 본문(500자 이내), 일시
  - **지역**: **"부천" 기본값으로 고정 바인딩**(수정 불가). `OPEN_REGIONS`에 지역이 추가되면 그때 선택형으로 전환
  - **상세 위치**(선택, 30자 이내): 자세한 장소를 적을 수 있게 하되 **가게 이름까지는 안 적어도 되게 유도**해요.
    - 입력창 placeholder: "예) 상동역 근처, 부천역 인근"
    - 도움말: "가게 이름까지는 적지 않아도 돼요. 자세한 장소는 참석하는 분들과 댓글로 정해요."
    - 탭 한 번으로 채우는 칩(예: 부천역, 상동역, 중동역, 송내역, 역곡역, 소사역)은 `regions.ts`에서 설정
  - **최대 인원**(필수, **리더 포함** 2~10명), **최소 확정 인원**(선택)
- 템플릿 칩: "해장국 같이 먹어요", "볼링 한 게임", "카페에서 수다" 등 원탭으로 제목·인원 기본값 채움
- 개설하면 리더가 자동으로 1자리를 차지해요.
- **남용 방지(누구나 개설하므로 필수)**: 설정값 `BUNGAE_LIMITS`
  - 1인당 하루 개설 2건, 동시 진행 3건 이내
  - 일시는 지금부터 1시간 이후 ~ 14일 이내
  - 신고 3건 이상 누적 시 자동 `pending_review`(비노출) + 관리자 큐
  - 제재 중인 사용자는 개설 불가
  - 제목·본문은 금칙어 필터 + AI 필터(11장)
- 개설 화면 하단에 안전 수칙 안내: "공개된 장소에서 만나요. 낯선 사람에게 개인정보를 알려주지 마세요."
- 개설 완료 시 전면형 광고 조건 노출(8-1)

**목록**
- **상단에 지역 안내 배너**("지금은 부천 지역 위주로 진행돼요…", 항상 노출)
- 카드: 제목, 일시, 지역(부천 + 상세 위치), **"N자리 남았어요"**, 마감 임박 배지(1~2자리 남음)
- **참석자 정보는 목록·미참석자 상세에 노출하지 않아요.**
- 필터: 날짜. 정렬: 임박순 기본

**상세**
- **미참석자**: 리더가 올린 내용(본문, 일시, 지역·상세 위치)과 **남은 자리**만 표시. 몇 명이 참석했는지·누가 참석했는지는 보이지 않아요.
- **참석 신청 후**: **현재 참석 인원, 참석자 목록(닉네임 + 성별 + 연령대)**, 참석자 전용 댓글이 열려요. (참여를 늘리려는 장치예요)
- 참석 신청은 즉시 확정(승인 없음). 정원 초과는 서버에서 트랜잭션으로 차단(동시 신청 경합 처리)
- 참석 취소: 모임 시작 N시간 전까지 가능(기본 3시간, 설정값). 취소한 이력은 상태로 남기되 화면에서는 제외
- 최소 확정 인원이 설정된 경우: 미달이면 "n명 더 모이면 열려요" 표시, 시작 전까지 미달이면 자동 마감(상태 `cancelled_min`)
- 리더는 자신의 벙개를 **취소**할 수 있고, 취소되면 참석자에게 표시돼요
- 상태: `open`(모집중) / `full`(마감) / `closed`(종료) / `cancelled`
- 하단 배너 광고(8-1), 종료 후 후기는 MVP 제외

**안전**
- 신고(벙개·댓글·사용자), 사용자 차단(차단하면 상대의 글·댓글이 안 보이고 참석자 목록에서도 표시 제한)

### 5-4. 수다방 (스레드형 SNS 피드, 카테고리 없음)
"게시글을 쓰는 느낌"이 아니라 **누구나 짧은 글을 툭 올리고 댓글이 달리는 SNS(Threads) 느낌**이에요. **카테고리·태그·게시판 구분을 만들지 마세요.**

**화면 구성**
- 최상단: 컨셉 배너(5-0의 1안), 그 아래 **인라인 작성 바**("오늘 퇴근길은 어땠어요?" 등 placeholder). 탭하면 작성 시트가 바로 열려요
- 상단 보조 줄: **정렬 토글(지금 / 인기)**. 지금=최신순, 인기=최근 24시간 좋아요·댓글 가중. (카테고리가 아니라 정렬이에요)
- 선택 표시: **지금 깨어 있는 사람 N명**(실제 활동 사용자 수만, **3명 미만이면 숨김**. 가짜 숫자 금지), **근무 상태 한 탭**(출근 / 퇴근 / 쉬는 날. 퇴근 선택 시 "오늘도 수고했어요" 등 고정 문구 풀에서 랜덤)
- 무한 스크롤, 당겨서 새로고침, 글 등록 즉시 피드 최상단 반영(낙관적 업데이트)

**글 카드**
- 닉네임 + (근무 유형 배지, 설정한 경우) + 시간("방금 전", "새벽 3:12" 같은 표시) + 본문 + 좋아요/댓글 수 + 더보기(신고·차단·내 글 삭제)
- 본문 500자 이내, 줄바꿈 허용, 텍스트만(이미지는 2차). 외부 링크는 **클릭되지 않는 텍스트**로 표시(스팸·유도 방지)

**글쓰기**
- 시트 상단 문구: "새벽에 일하는 우리끼리, 편하게 남겨요"
- 글자 수 카운터, 한 번에 등록. 수정은 등록 후 10분 이내, 삭제는 언제든 가능
- 등록 즉시 완료 처리하고, **전면형 광고는 등록 성공 후 화면 전환 시점**에 조건부로 노출(8-1). 광고 때문에 등록이 지연·실패하면 안 돼요

**댓글·좋아요**
- 글 상세에서 댓글이 **스레드처럼 이어져 보이고**, 답글은 1단계까지
- 좋아요: 글·댓글 토글, 중복 불가
- 글 상세 하단에 배너 광고(8-1)

**시스템 스레드**
- 매일 새벽 시간에 "오늘 퇴근길 한마디" 같은 **주제 글**을 시스템 계정("새벽사람들 운영팀" 표기)이 자동으로 올려 피드 상단에 고정해요. 가짜 유저·가짜 글은 만들지 마세요.

**위기 문구 안내**
- 자살·자해를 암시하는 문구가 감지되면 **작성자에게만** "힘든 시간을 보내고 있다면 도움받을 수 있어요" 안내 시트(상담전화 번호)를 보여줘요. 공개 표시나 낙인 표시는 하지 않아요. 번호는 개발 시점에 공식 사이트에서 재확인(11장)

**신고·차단**: 모든 글·댓글에서 가능

### 5-5. 내정보

## 7. 로그인 (플랫폼 어댑터)

### 7-1. Phase 1 (웹): Supabase Auth
- 이메일(매직링크 또는 비밀번호) 우선. 소셜 로그인은 추후.
- 로그인 이후 온보딩 완료 여부를 `profiles` 존재 여부로 판단.

### 7-2. Phase 2 (앱인토스): 토스 로그인 — 검증 필요 사항 포함
공식 문서 기준(다시 확인 후 진행):
- 클라이언트: `appLogin()`으로 인가 코드(`authorizationCode`, `referrer`)를 받아요. 코드는 10분, 1회용이에요.
- 서버: 인가 코드 → **AccessToken 발급** → **사용자 정보 조회**(`login-me`) → 연결 해제 시 **콜백 수신**.
- 사용자 정보 필드는 **AES-256-GCM으로 암호화**되어 오고, 복호화 키는 콘솔에서 받는 값이에요.
- **서버 간 통신은 mTLS 인증서가 필수**예요.
- 동의 항목: 이름·이메일·성별(필수 계열), **생일(선택)**. 지역은 제공되지 않아요 → **콘솔에서 생일을 필수 동의로 설정**해야 만 19세 판별이 가능해요(제가 콘솔에서 설정할게요).
- **미니앱에서는 토스 로그인만 허용**돼요. 자체 로그인은 앱인토스 안에서는 쓰지 않아요.

### 7-3. mTLS 서버 (기술 리스크 — PoC 먼저)
- 개발자 커뮤니티 확인 결과 **Supabase Edge Function은 mTLS 클라이언트 인증서를 쓰지 못해요.** Supabase Edge Function에서 토스 서버를 직접 호출하는 설계는 하지 마세요.
- 후보(비용 낮은 순으로 PoC하고 결과를 알려주세요):
  1. **Vercel Node.js 서버리스 함수**에서 `https.Agent`에 인증서·개인키(환경변수, base64)를 넣어 호출 → 가능한지 먼저 확인
  2. Cloudflare Workers의 mTLS 바인딩
  3. Fly.io/Railway 등 소형 Node 서버(월 비용 발생 → **생성 전 저에게 확인**)
- 흐름: `클라이언트 appLogin` → `POST /api/auth/toss`(인가 코드) → 서버가 토큰 발급·사용자 조회·복호화 → `userKey`로 Supabase 사용자 조회/생성 → **Supabase 세션 발급**(admin API 기반 방식, 예: 서버가 사용자에 대해 세션을 생성. 안전한 방식을 조사해서 제안) → 클라이언트에 세션 반환
- `userKey`는 앱별 고유값이므로 `profiles`에 `toss_user_key`(unique)로 저장.
- `POST /api/auth/toss/unlink`(콜백 엔드포인트): 토스 콜백 인증 방식을 문서에서 확인해 검증하고, 6-3 삭제 처리를 실행.
- 인증서·키·복호화 키는 **Vercel 환경변수**에 보관하고 저장소에 절대 넣지 않아요. 로컬 테스트는 인증서 없이 **mock 어댑터**로 진행.
- 앱인토스 밖(웹)에서 토스 로그인은 별도 계약이 필요할 수 있으니 **웹은 계속 Supabase Auth**로 가요.

## 11. AI 기능 (Anthropic)

### 11-1. 용도
1. 게시물·댓글·벙개 제목/본문의 **비속어·불법·선정 콘텐츠 1차 필터**
2. **모든 글**의 **위기 문구(자살·자해 암시) 감지** → **작성자에게만** 도움 안내 시트 노출

### 11-2. 구조
- 인터페이스: `moderate(text): { allowed: boolean; categories: string[]; severity: 0-3; crisis: boolean }`
- Provider 3종을 환경변수 `AI_PROVIDER=mock|claude-cli|anthropic`로 선택:
  - `mock`: 규칙 기반(금칙어), 테스트용
  - `claude-cli`: **로컬 개발 전용**. Node `child_process`로 `claude -p`를 호출(API 비용 없음). `NODE_ENV=production`에서는 **절대 동작하지 않게 차단**
  - `anthropic`: 배포용. Anthropic API. **키는 서버(`api/`)에서만** 사용
- 모델은 환경변수(`ANTHROPIC_MODEL`)로 지정하고, **저비용 소형 모델**을 기본으로 하세요(공식 문서에서 최신 모델명을 확인).
- **금칙어 규칙 필터를 먼저** 돌리고, 통과한 텍스트만 AI로 보내 비용을 줄여요.
- 처리 방식: 글 저장 직후 **비동기 검사** → 문제 있으면 `pending_review`/`hidden`으로 전환하고 관리자 신고 큐에 추가. AI 호출 실패 시에는 규칙 필터 결과만 적용하고 **서비스가 멈추지 않게** 해요.
- 위기 감지는 **글 삭제가 아니라 안내 노출**이 기본이에요. 자살예방상담전화 번호와 운영 기관은 **개발 시점에 공식 사이트(보건복지부·한국생명존중희망재단)에서 재확인**하고 상수로 관리하세요. (참고: 2024년 1월부터 **109**로 통합)

### 11-3. 안전·비용
- 사용자 글은 **데이터로만** 취급해요. 글 안의 지시문이 프롬프트를 바꾸지 못하게 구분자로 감싸고, 출력은 JSON 스키마로 검증하세요(프롬프트 인젝션 방어).
- AI에는 **텍스트만** 보내요(닉네임·userKey·지역 등 식별 정보 제외).
- 일일 호출 상한(`AI_DAILY_LIMIT`)과 사용량 로그를 두어 **API 비용이 폭주하지 않게** 해요. Anthropic 결제 한도는 30달러예요.
- 프롬프트는 `src/server/ai/prompts/`에서 버전 관리해요.
